# Demo Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify live the eleven demos of the demo set, then tag omnia-demo v0.2.0.

**Architecture:** Most demos reuse an existing agent and need a live check and a runbook. The new work is reshaping `pii-chat` into Larkmere's member assistant (identity from the signed-in portal, memory on, no SSN in chat), its canary and redaction beats, a `halvern-research` workspace with a mock-priced research function under a budget, knowledge retrieval for claims triage, and a re-ingest beat for the field manual.

**Tech Stack:** Helm chart `charts/omnia-demo`, Go stubs (`demos/mortgage-underwriting`, `demos/demo-sites`, `demos/card-callers`), PromptArena kits compiled by `hack/build-packs.sh` with packc 1.5.2, Omnia 0.9.0-beta.23 on `aks-omnia-demo`, omnia-azure `make workspace`.

**Spec:** `docs/superpowers/specs/2026-11-12-demo-set-design.md`

## Global Constraints

- Every demo is a use case a real company would implement, done the way it would implement it. No identity proven in chat; no control that is really a prompt.
- Fix stand-ins and our config; ticket Omnia bugs on AltairaLabs/Omnia, "Target: 0.9.0-beta.24"; hold a demo that can't be shown honestly. Read the docs and state the design intent before fixing unexpected Omnia behaviour (AGENTS.md).
- Never loosen a security gate (authentication, subject proofs, tenancy, network policy, workload identity, Key Vault).
- Only Larkmere Mutual, Wrenmoor Energy and Halvern Partners. Every page keeps the fictional-company disclaimer.
- Work stays local on omnia-demo `feat/demo-plan` and omnia-azure `feat/dev-registry`; one omnia-demo PR at the end. No tag until all eleven demos are verified live, including those held on Omnia.
- Every command names its cluster: `kubectl --context aks-omnia-demo`, `helm --kube-context aks-omnia-demo`. Never `use-context`.
- Commits: conventional, `git commit -s`, message by heredoc into `git commit -F -`. No `$()` and no `cd x && y` in commands.
- Images: `make images` builds into the dev registry; `make demos TENANTS=<t>` deploys. Packs: `env PACKC=<packc 1.5.2> hack/build-packs.sh <demo>`; the installed `packc dev` is stale.
- A demo is marked Live in the catalogue only once its runbook has been followed end to end against a real model.

## Review Focus

1. **A member with no verified user.** If the portal's token is missing or its issuer untrusted, the member assistant gets no memory tools and its card tools see no member. It must refuse to act on a card, never act on a default member. Test: the stub refuses freeze with no `X-Omnia-User-Email` (Task 1).
2. **Two members at once.** The canary's callers and Ellen talk to the same agent concurrently. One member's memories or card must never reach another. Test: stub freeze for one email leaves another's card active (Task 1); live check that a caller's `memory_context` holds no Ellen (Task 4).
3. **Re-running a canary.** The gate averages every result ever recorded for an eval id (Omnia #3950), so a second run on the same id is decided by the first. `make canary` must refuse a run whose eval id already has results, rather than mislead. Test in Task 3.
4. **A cap reached mid-batch.** Runs after the cap must be refused, not queued or silently dropped, and the runbook's batch script must report how many were refused. Test in Task 6.
5. **A pasted card number in a memory.** A case note quoting the number must be stored redacted, as must the transcript. Live check in Task 2.
