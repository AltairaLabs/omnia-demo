# Seed Memories for Arena Scenarios

**Status**: Proposed upstream feature for PromptKit
**Created**: 2026-04-12
**Target repo**: AltairaLabs/PromptKit

---

## Problem

Arena scenarios that test memory recall across sessions cannot pre-populate the memory store. The hero-memory-recall scenario simulates a returning customer (Sarah Chen, who previously had a delayed order resolved with an EXPRESS_UPGRADE discount), but the in-memory store is empty at scenario start — there's no prior session to recall from.

The existing memory-agent examples work around this by using multi-turn scenarios where early turns store memories and later turns recall them. This doesn't work when the scenario models a *separate session* with prior context, which is the core demo use case for memory.

## Design

### Schema

New optional field `seed_memories` on `ScenarioSpec`. Supports inline entries or a file reference.

#### Inline form

```yaml
spec:
  seed_memories:
    - content: "Sarah Chen contacted support about order #1023 (Summer Linen Dress, $89). The order was delayed 5 days in transit. Agent confirmed the delay via lookup_order, apologized, and issued an EXPRESS_UPGRADE discount code."
      tags: [sarah-chen, order-1023, delay, express-upgrade, resolved]
    - content: "Sarah was stressed about the delay because she needed the dress for a birthday party. She was relieved when offered the express upgrade."
      tags: [sarah-chen, order-1023, emotional-context]
```

#### File reference form

```yaml
spec:
  seed_memories:
    file: fixtures/sarah-prior-session.memories.yaml
```

Where the file contains a flat list of the same entries:

```yaml
# fixtures/sarah-prior-session.memories.yaml
- content: "Sarah Chen contacted support about order #1023..."
  tags: [sarah-chen, order-1023, delay, express-upgrade, resolved]
- content: "Sarah was stressed about the delay..."
  tags: [sarah-chen, order-1023, emotional-context]
```

#### Entry shape

Each entry has two fields:

- `content` (string, required) — the memory text that `memory__recall` searches against via substring matching
- `tags` (string list, optional) — stored as metadata on the memory entry

No IDs, timestamps, scope, or provenance. The engine generates these at load time. Hybrid inline + file is not supported — pick one per scenario.

### Engine behavior

Seeding happens in `execution.go` (or equivalent), after `registerMemoryForRun()` creates the per-run scope but before the first turn executes:

1. Iterate `seed_memories` entries (resolved from inline or file during config loading).
2. For each entry, call `store.Save()` with:
   - `Content` from the YAML entry
   - `Scope` matching the run scope (same `scenario` + `runID` keys from `registerMemoryForRun`)
   - `Tags` from the YAML entry (or empty slice)
   - `ID` auto-generated by the store
   - `CreatedAt` set to `time.Now()`
3. Log one INFO line: `"Seeded N memories for scenario" scenario=<id> count=<N>`

If the memory store is nil (memory not enabled), skip seeding with a WARN log. No error — graceful degradation.

No changes to `memory__recall`, `memory__remember`, or any other runtime memory behavior. Seeded entries are indistinguishable from entries created by `memory__remember` — they're just pre-existing rows.

### File loading

File path is relative to the **arena config file's directory** (the same base path used for tool files, provider files, and scenario files). For example, if `config.arena.yaml` is at `acme-apparel-support/config.arena.yaml` and the seed file is `fixtures/sarah-prior-session.memories.yaml`, the resolved path is `acme-apparel-support/fixtures/sarah-prior-session.memories.yaml`. This matches how `mock_result` file references work in tool definitions. The file is loaded during config parsing alongside the scenario. The file is a YAML list of `{content, tags}` objects.

### Validation

Added to `promptarena validate`:

| Check | Severity | Message |
|---|---|---|
| `seed_memories` present but `memory: { enabled: true }` not set | WARN | "scenario X has seed_memories but memory is not enabled in the arena config" |
| Entry with empty `content` | ERROR | "seed_memories entry N has empty content" |
| File reference doesn't exist | ERROR | "seed_memories file not found: path" |

Runtime check in `promptarena run`:

| Check | Behavior |
|---|---|
| `seed_memories` present but memory store is nil | WARN log, skip seeding |

### JSON Schema changes

Add `seed_memories` to `ScenarioSpec` in `schemas/v1alpha1/scenario.json`:

```json
"seed_memories": {
  "description": "Pre-populate the memory store before the scenario starts. Inline list or file reference.",
  "oneOf": [
    {
      "type": "array",
      "items": {
        "$ref": "#/$defs/SeedMemoryEntry"
      }
    },
    {
      "type": "object",
      "properties": {
        "file": {
          "type": "string",
          "description": "Path to a YAML file containing seed memory entries, relative to the scenario file"
        }
      },
      "required": ["file"],
      "additionalProperties": false
    }
  ]
}
```

With `SeedMemoryEntry`:

```json
"SeedMemoryEntry": {
  "type": "object",
  "properties": {
    "content": {
      "type": "string",
      "description": "Memory text that memory__recall searches against"
    },
    "tags": {
      "type": "array",
      "items": { "type": "string" },
      "description": "Optional metadata tags"
    }
  },
  "required": ["content"],
  "additionalProperties": false
}
```

## Example: hero-memory-recall with seed memories

```yaml
apiVersion: promptkit.altairalabs.ai/v1alpha1
kind: Scenario
metadata:
  name: hero-memory-recall
spec:
  id: hero-memory-recall
  task_type: acme-support-variant-a
  seed_memories:
    - content: "Sarah Chen contacted support about order #1023 (Summer Linen Dress, $89). The order was delayed 5 days in transit. Agent confirmed the delay via lookup_order, apologized, and issued an EXPRESS_UPGRADE discount code for her next order."
      tags: [sarah-chen, order-1023, delay, express-upgrade, resolved]
    - content: "Sarah was stressed about the delay because she needed the dress for a birthday party this weekend. She was relieved when offered the express upgrade."
      tags: [sarah-chen, order-1023, emotional-context]
  turns:
    - role: user
      content: |
        Hi, I'm back — the dress arrived this morning and it's perfect. Thank you for sorting out the express shipping, the party's this afternoon.
    - role: claude-user
      persona: sarah-chen
      turns: 2
  conversation_assertions:
    - type: tools_called_session
      params:
        tools: [memory__recall]
      message: Agent should call memory__recall at session start to load prior context
    - type: contains_any
      params:
        patterns: ["glad to hear", "so pleased", "happy", "great news", "wonderful"]
      message: Agent should respond warmly to a successful resolution callback
```

## What this does NOT cover

- **Cross-scenario memory persistence** — each run gets a fresh scope. Seeding is the mechanism for simulating prior sessions.
- **Vector search** — the InMemoryStore uses substring matching. Seed content should be written with recall queries in mind.
- **Memory export/import** — no mechanism to capture memories from one run and feed them into another. Seed memories are authored by hand.
- **Scope customization** — seed entries inherit the run scope automatically. No per-entry scope overrides.
