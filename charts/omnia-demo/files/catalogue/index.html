Omnia demo catalogue

Every demo on this install, by tenant. Each tenant is its own Omnia workspace, so the same person has different pseudonyms in each, nothing is shared between them, and each has its own budget. Links open the dashboard scoped to that workspace.

The numbers are an order to show them in, from familiar ground to what only a platform does: 1–2 an agent run properly, 3–5 guardrails you can't prompt your way to, 6–8 it knows your customers safely, 9–10 change it without breaking it, 11 learn from it, 12 build your own. Held means built and waiting on an Omnia fix.

Each numbered demo has a How to run it panel: what to set up, what to click and type, what to point at, and how to reset for the next take. The full runbook it links to has the detail and the gotchas.

Before you start

  1. Sign in to this dashboard (you have, if you can read this). Every agent, session and policy below is shown from here.
  2. Get a terminal with a checkout of omnia-demo (commands below run from its root) and kubectl access to the cluster. Every command names the cluster with --context "${KUBE_CONTEXT:?set KUBE_CONTEXT to your cluster's context}", so set it first to the cluster's kube context (the aks.kubeContext in your deploy/azure/site.yaml): 
    export KUBE_CONTEXT=<your cluster's kube context>
  3. Is the cluster up? If the dashboard doesn't load, start your cluster if it is stopped to save credits, and allow about ten minutes for it to come back.
  4. Open the customer sites for demos 1 and 6–8, each in its own terminal, and leave them running: 
    kubectl --context "${KUBE_CONTEXT:?set KUBE_CONTEXT to your cluster's context}" -n wrenmoor-energy port-forward svc/wrenmoor-site 8894:8080
#   Wrenmoor customer portal (Amira Saleem):  http://localhost:8894/ui_kits/portal/
kubectl --context "${KUBE_CONTEXT:?set KUBE_CONTEXT to your cluster's context}" -n larkmere-mutual port-forward svc/larkmere-portal 8890:8080
#   Larkmere member portal (Ellen Whitcomb):   http://localhost:8890/ui_kits/portal/
  5. Keep two windows side by side for the customer demos: the customer's site on one side, this dashboard on the other. Talk to agents as the customer on the site, never from the dashboard Console; show the record from the dashboard.

Everything runs on a real model, so wording varies from take to take. If an answer surprises you, say so and run it again; never change the setup to fit the take.
